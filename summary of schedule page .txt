# Schedule Rendering Algorithm Summary in details

## **Core Problem**
Display overlapping sessions in a weekly calendar grid where multiple sessions can occur at the same time without visual collision.

## **Algorithm Overview**

### **1. Data Structure**
```javascript
// Input: Sessions grouped by day with time strings
sessionsByDay = {
  Monday: [
    { id: 1, start_time: "09:00", end_time: "10:30", class_id: 1 },
    { id: 2, start_time: "09:15", end_time: "10:15", class_id: 2 }
  ]
}

// Convert to minutes for calculation
convertedSessions = [
  { id: 1, startTime: 540, endTime: 630 }, // 9:00-10:30 in minutes
  { id: 2, startTime: 555, endTime: 615 }  // 9:15-10:15 in minutes
]
```

### **2. Core Data Structures**
- **`block`**: Object with column indices as keys, arrays of active sessions as values
- **`pointer`**: Tracks current position in sorted sessions array
- **`toDisplay`**: Sessions to render in current hour row

### **3. Hour-by-Hour Processing**
For each hour slot (e.g., 9:00-10:00):

#### **Step 1: Block Cleanup**
```javascript
blockFilter(block, hourStartMinutes);
// Removes sessions that ended before current hour
// block[0] = [session1] → block[0] = [] if session1.endTime < hourStartMinutes
```

#### **Step 2: Session Collection**
```javascript
while (pointer < sessions.length && sessions[pointer].startTime < hourEndMinutes) {
  const newSession = sessions[pointer];
  pointer++; // Move to next session
  
  // Process this session...
}
```

#### **Step 3: Column Allocation (Collision Detection)**
```javascript
function findFreeColumn(block, newSession) {
  // Check each existing column
  for (let i = 0; i < blockLength; i++) {
    const sessions = block[i] || [];
    const overlaps = sessions.some(existingSession => 
      // Check if times overlap: !(A.end <= B.start || B.end <= A.start)
      !(existingSession.endTime <= newSession.startTime || 
        newSession.endTime <= existingSession.startTime)
    );
    if (!overlaps) return i; // Found free column
  }
  return blockLength; // Create new column
}
```

#### **Step 4: Position Calculation**
```javascript
newSession.colIndex = freeCol;
newSession.top = newSession.startTime - hourStartMinutes; // Vertical offset
newSession.height = newSession.endTime - newSession.startTime; // Duration
newSession.left = newSession.colIndex * SESSION_WIDTH; // Horizontal position
```

#### **Step 5: Update Data Structures**
```javascript
block[freeCol].push(newSession); // Add to active block
toDisplay.push(newSession); // Add to current hour display
```

### **4. Visual Rendering**
```jsx
// Each session positioned absolutely within hour row
<div style={{
  position: 'absolute',
  top: `${session.top}px`,      // Minutes from hour start
  left: `${session.left}px`,    // Column * width
  height: `${session.height}px`, // Duration in minutes
  width: `${SESSION_WIDTH}px`   // Fixed column width
}} />
```

## **Key Algorithm Features**

### **Time Complexity**
- **O(S)** where S = total sessions (each session processed once)
- **Collision detection**: O(C×A) where C = columns, A = active sessions per column

### **Space Efficiency**
- **Block object**: Only stores sessions spanning current time
- **Memory cleanup**: Expired sessions automatically removed each hour

### **Collision Resolution**
- **Column-based**: Each overlapping session gets its own column
- **Optimal packing**: Always uses the leftmost available column
- **Dynamic width**: Row width adjusts based on maximum concurrent sessions

### **Cross-row Sessions**
- Sessions longer than 1 hour span multiple rows
- Only rendered once (at start time) with calculated height
- Z-index ensures clickability across row boundaries

## **Example Execution**
```
Hour 9:00-10:00:
├── Session A (9:00-10:30) → Column 0, height: 90min
├── Session B (9:15-10:15) → Column 1, height: 60min
└── Session C (9:30-10:00) → Column 2, height: 30min

Result: 3 columns, row width = 360px (3 × 120px)
```

This algorithm efficiently handles any number of overlapping sessions while maintaining visual clarity and interactive functionality.
